# Workbook repair, phase 1: frozen source baseline

Phase 1 adds comparison tooling and local reference evidence. It does not change
the extraction engine, statement parser, workbook writer, or desktop application.

## Preserved artifacts

The local baseline is `outputs/repair-baseline-20260921/` (ignored by Git).

- `source.pdf`: a byte-for-byte copy of the user-selected filing.
- `old.xlsx`: the output from committed version `26985d1`.
- `new.xlsx`: the original output from the uncommitted version.
- `corrected.xlsx`: the subsequent output with the income statement presentation restored.
- `working-source.zip` and `working-tree.patch`: source state at the start of this
  repair phase. This does not reconstruct historical uncommitted code for earlier runs.
- `manifest.json`: original locations, SHA-256 hashes, Git HEAD and snapshot provenance.
- `expected.json`: independent source-row transcription, source line IDs, raw
  numeric tokens, reporting contexts, headings and comparison limits.
- `source-pages/`: extracted text for physical PDF pages 3-9 and selected visual references.
- `reports/phase1-final/`: the reviewed comparison report and full machine-readable results.

Other comparison folders are development
diagnostics, not the accepted phase-1 report.

The expected JSON is generated by the local `build_reference.py`, which uses
explicit source line ranges and handles wrapped source rows separately. It never
imports the production statement parser or treats an existing workbook as truth.
The reference keeps source dashes distinct from zero. Workbook blanks and dashes
are treated as equivalent missing amounts for the numeric comparison only.

## Repeat the comparison

From the project root:

```powershell
.\.venv\Scripts\python.exe scripts\compare_workbook_baseline.py `
  outputs\repair-baseline-20260921 --report-dir tmp\repair-comparison-001
```

To check a future repair alongside all three preserved versions:

```powershell
.\.venv\Scripts\python.exe scripts\compare_workbook_baseline.py `
  outputs\repair-baseline-20260921 `
  --candidate "phase2=C:\Path\To\Candidate.xlsx" `
  --report-dir tmp\repair-comparison-002
```

Use a new report directory each time. The command verifies baseline file hashes
before reading workbooks and refuses to overwrite a report directory.
Exit code 1 means differences were found; this is expected for the preserved
workbooks. Exit code 2 means an input/integrity error. With `--candidate`, the
exit status reflects candidates, not the known defects in the frozen versions.
Exit code 0 means no differences were detected by these bounded checks, not that
the filing or workbook has been certified.

## Comparison rules

- Locate statement sheets by the full source title in A2, not their generic tab names.
- Match source labels and complete selected numeric row vectors, retaining the
  multiplicity of genuine equal source rows before reporting excess duplicates.
- Report missing rows, excess duplicates, changed amounts, insufficient numeric
  columns and row ordering separately. Equal counts or equal totals cannot hide
  missing rows or changes to individual amounts.
- Report missing headings, inconsistent physical column positions, labels with
  embedded data, unrecognized numeric rows, total emphasis and sheet dimensions.
- Keep a normal em dash separate from the Unicode replacement character.
- Compare shared raw extraction tables by table ID and record added/removed tables.
- Keep source IDs and workbook row/column references in `comparison.json`.

Matching can recover labels around an isolated footnote marker, as in the cash
reconciliation total. It does not generally reconstruct arbitrary wrapped labels.
Unexpected layouts remain visible as unresolved rows or missing statements.
Header presence and consistent columns are useful diagnostics, not proof of every
period/component association. Source visual review remains required.

## Known failures established by this baseline

- All versions omit the 31-row balance sheet.
- Income amounts match all 40 source rows. The original new workbook loses the
  duration headings; the corrected workbook restores them. The old/corrected
  presentation still joins the per-share section heading to its first data label.
- The old cash-flow presentation omits the reconciliation total and its distinct
  September 2025 date. The new/corrected presentation recovers that section but
  loses three supplemental rows.
- The old equity output omits four total-change rows and leaves the remaining
  component amounts embedded in labels. New/corrected output matches all 39 rows
  numerically, but loses component headings and uses two different column patterns.
- The new/corrected schedule contains 186 excess investment rows plus six excess
  subtotal rows: three copies of the selected source tables. The old schedule has
  the source rows but fails to separate their numeric components.
- Shared raw table contents are unchanged. Adaptive extraction skips Camelot on
  page 5; all original PDFPlumber tables remain available.

## Validation

Synthetic tests in `tests/test_workbook_baseline.py` exercise legitimate equal
rows, duplicates concealing omissions, equal-total numeric changes, missing versus
zero, invalid numeric tokens, incomplete columns, neighboring-label confusion,
year headers, shifted columns, embedded amounts, missing statements, file
preservation, baseline hash failures, row ordering and em-dash decoding.

Completed checks: all 292 project tests, Ruff, dependency checks and package build
passed. The real saved-workbook comparison reproduces the known failures, and a
disposable copy with one deliberately changed income amount reports exactly that
changed field. Baseline hashes, original input files, and all pre-existing project
source files were verified unchanged. Results are recorded in
`reports/phase1-final/acceptance.json`.

Do not add the real PDF or workbook fixtures to Git. Later phases should add
synthetic regression cases and use this local baseline as an acceptance check.
